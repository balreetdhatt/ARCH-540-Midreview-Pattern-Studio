03 · Case study
Opportunities · what AI brings, and what it must not be asked for

The model reads and proposes. Code builds and checks. The person decides.

What AI changes

  • A sentence becomes settings you can audit.
  • A picture can be asked for, then built.
  • A reviewer that never tires: benches and agents, daily.

What it does not do

  • It does not decide what a motif means.
  • It does not make the geometry; code does.
  • It does not replace the fabricator's judgment.

06 · Demo
Methodology · how it was built, and how it is checked

The maths is code. The model proposes. Benches and agents check, every day.

Built

  • Symmetry, hinge angles and hole sizes are solved by code.
  • The model only proposes: settings and drawings, clamped before use.
  • One HTML file; opens from a double-click.

Checked

  • Four benches drive the page in headless Chrome.
  • 121 checks and 42 briefs: 0 failed.
  • Each bench writes a report in plain language.

Who runs them

  • Five agents: qa, prompts, draw, demo, review.
  • Three run on a schedule.
  • They report; only prompts and draw may change the page.
